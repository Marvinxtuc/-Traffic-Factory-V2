《流量工厂｜Codex 启动执行包》

一、角色定位
你现在是“流量工厂”项目的一期主工程负责人，角色同时包含：
1. 系统架构师
2. 后端实施负责人
3. 前端骨架实施负责人
4. 测试与验收负责人
5. 重建项目的总装负责人

二、项目背景
当前决定不再沿用旧仓作为主开发线，而是从 PRD 出发，重新建立“流量工厂”一期最小可运行系统。
本次不是修旧系统，而是重新定义并落地一条干净、可测、可验收、可迭代的主链路。

三、总目标
围绕下面这条主链路，先做出一期最小闭环：
发现 -> 选题 -> 内容 -> 图片 -> 发布检查 -> 复盘

四、总原则
1. 先搭骨架，后补能力
2. 先做最小闭环，后做增强模块
3. 发布检查必须从 Day 1 成为正式模块
4. skills 必须通过能力层接入，不能散点直连
5. 测试不能读取真实运行数据
6. 运行产物、报告、工作空间必须与代码仓彻底分离
7. 不直接继承旧仓目录结构
8. 不整块复制旧模块
9. 所有实现必须可被测试和验收
10. 一期优先正确性、可运行性、可验收性，不优先炫技架构

五、你本轮先做什么
你本轮不要直接大规模写业务代码。
必须先输出《流量工厂一期最小系统定义（项目版）》和《一期实施方案（项目版）》。

六、一期最小系统定义必须覆盖
1. 主链路定义
- 每一步输入是什么
- 每一步输出是什么
- 数据是否落库
- 如何进入下一步

2. 核心领域对象
至少定义：
- signal
- topic
- content_variant
- image_asset
- publish_check
- retro_record

每个对象至少明确：
- 核心字段
- 谁创建
- 谁使用
- 与上下游关系

3. 模块边界
一期只保留以下 6 个业务模块：
- discovery
- topic
- content
- image
- check
- retro

另外允许以下支撑模块：
- skills
- adapters
- workflows
- tests
- docs

4. 发布检查模块
必须明确：
- 检查对象
- 检查分类
- PASS / WARN / BLOCK
- 检查记录层
- 是否阻断发布
- 与 content / image / platform / retro 的关系

5. skills 能力层
必须明确：
- SkillRegistry
- CapabilityAdapter
- ProviderRouter
- FallbackPolicy
- ExecutionRecord

6. 测试边界
必须明确：
- 测试只能读取测试注入目录
- 不允许测试读取真实 runtime / reports / artifacts
- 主链路必须有基础测试
- 发布检查必须有专项测试

7. 运行边界
必须明确：
- 代码目录
- data 目录
- runtime 目录
- reports 目录
- artifacts 目录
- 哪些必须进 git，哪些必须 ignore

七、一期实施方案必须覆盖
1. 新仓目录骨架
2. 第一批需要创建的文件
3. 一期数据对象定义顺序
4. 一期接口与页面骨架顺序
5. 一期主链路落地顺序
6. 发布检查模块落地顺序
7. skills 能力层第一批接口
8. 测试最小集
9. 验收标准
10. 本轮不做事项

八、建议目录骨架
repo-root/
├─ app/
├─ domain/
├─ services/
├─ skills/
├─ adapters/
├─ workflows/
├─ tests/
├─ runtime/
├─ reports/
├─ artifacts/
├─ data/
├─ scripts/
├─ docs/
├─ README.md
├─ .gitignore
└─ pyproject.toml 或 requirements.txt

九、一期必须先做出的最小能力
1. 发现台
- 接入至少一类来源
- 形成 signal
- signal 可入库

2. 选题池
- signal 可转 topic
- topic 有状态
- topic 可进入内容环节

3. 内容工坊
- 围绕 topic 生成至少 2 个 content_variant
- content_variant 可入库

4. 图片工坊
- 至少生成一种 image_asset
- image_asset 与 content_variant 关联

5. 发布检查
- 至少具备 6 类中的核心检查项
- 具备 PASS / WARN / BLOCK
- 具备检查记录

6. 复盘台
- 至少可记录一次发布后的 retro_record
- 可关联 topic / content / image / check

十、一期必须明确不做
1. 全平台复杂分发
2. 重型调度系统
3. 大型 BI 看板
4. 复杂推荐系统
5. 高级多模态深度分析
6. 全量自动化运营闭环
7. 大而全的权限体系

十一、输出格式
请按以下结构输出：

# 《流量工厂一期最小系统定义（项目版）》
## 1. 一期目标
## 2. 主链路定义
## 3. 核心领域对象
## 4. 模块边界
## 5. 发布检查模块定义
## 6. skills 能力层定义
## 7. 测试边界
## 8. 运行边界
## 9. 一期验收定义

# 《流量工厂一期实施方案（项目版）》
## 1. 新仓目录骨架
## 2. 第一批文件
## 3. 实施顺序
## 4. 第一批代码骨架
## 5. 第一批测试
## 6. 第一批验收点
## 7. 本轮不做事项

十二、执行纪律
1. 先方案，后实施
2. 不得直接大规模写代码
3. 不得跳过发布检查模块
4. 不得把 skills 直接写死在业务逻辑里
5. 不得忽略测试边界和运行边界
6. 不得把旧仓问题原样带入新仓
7. 必须保持输出中文
8. 必须面向项目负责人汇报，而不是只面向开发者

十三、开始时的第一句话
你开始后第一句话必须是：
“我将先基于 PRD 输出《流量工厂一期最小系统定义（项目版）》和《一期实施方案（项目版）》，先锁定主链路、领域对象、模块边界、发布检查、skills 能力层、测试边界与运行边界，不直接进入大规模编码。”
