# V1 UI 中文规范（强制条款）

## 1. 适用范围
1.1 本规范适用于 `v1/web/discovery.html`、`v1/web/topics.html`、`v1/web/content.html` 与 `v1/web/assets/ui.js` 的全部用户可见文案。  
1.2 本规范适用于导航、页标题、模块标题、字段名、状态名、按钮文案、空态/加载/错误提示。  
1.3 本规范为一期默认口径，后续新增页面必须沿用本规范。

## 2. 文案来源规则
2.1 所有用户可见文案必须来自 `v1/web/assets/i18n_zh.js`。  
2.2 页面模板必须通过 `data-i18n` / `data-i18n-placeholder` 或 `TFUI.t()` 读取文案。  
2.3 禁止在页面模板与交互脚本中直接写死中文文案。  
2.4 禁止在页面模板与交互脚本中直接写死英文 UI 文案。  
2.5 文案新增或修改必须先更新 `i18n_zh.js`，再更新调用点。

## 3. 页面命名规则
3.1 页面名称固定：`发现台`、`选题池`、`内容工坊`。  
3.2 导航保留占位名称固定：`图片工坊`、`质检台`、`复盘台`、`帮助中心`、`账户`。  
3.3 页面 `<title>` 必须使用 `PAGE_TITLE` 映射，不得手写。

## 4. 模块命名规则
4.1 模块名称必须使用 `MODULE` 分组统一维护。  
4.2 `Signal Feed` 对应 `信号流`，`Signal Analysis` 对应 `信号分析`，`Metadata` 对应 `元数据`，`Operation Result` 对应 `操作结果`。  
4.3 同一模块在不同页面不得出现多个中文版本。

## 5. 字段命名规则
5.1 字段名必须使用 `FIELD` 分组统一维护。  
5.2 `Source` 对应 `来源`，`Status` 对应 `状态`，`Collected` 对应 `采集时间`，`URL` 对应 `链接地址`。  
5.3 表头、详情字段、筛选字段必须共用同一字段映射，不得各自命名。

## 6. 状态命名规则
6.1 后端内部状态枚举可保留英文值，前端展示必须通过 `STATUS` 映射输出中文。  
6.2 信号状态固定展示：`新信号`、`已审阅`、`已转选题`、`已归档`。  
6.3 选题状态固定展示：`待处理`、`进行中`、`已完成`、`已放弃`。  
6.4 内容任务状态固定展示：`排队中`、`生成中`、`已完成`、`失败`。  
6.5 禁止前端直接显示英文枚举值。

## 7. 操作按钮命名规则
7.1 按钮文案必须使用 `ACTION` 分组统一维护。  
7.2 主次动作固定口径：`转入选题`、`丢弃`、`开始写稿`、`执行生成`、`重新生成`、`刷新`、`重试`、`关闭`。  
7.3 禁止同一动作出现多个中文版本。

## 8. 空态/加载/错误规则
8.1 空态、加载态、错误态文案必须来自 `STATE`、`ERROR` 或页面专属映射分组。  
8.2 页面必须覆盖基础状态：`加载中`、`暂无数据`、`读取失败/请求失败`、`重试`。  
8.3 错误信息如来自后端英文 detail，前端必须进行中文归一化后再展示。

## 9. 允许保留英文白名单
9.1 仅允许以下英文保留在可见区域：`RSS`、`JSON`、版本号（如 `V1.0.4`）。  
9.2 白名单由 `WHITELIST.ENGLISH` 统一维护。  
9.3 白名单之外出现英文，视为规范违规。

## 10. 禁止规则（硬约束）
10.1 禁止页面直接写英文 UI 文案。  
10.2 禁止中英混合 UI。  
10.3 禁止状态直接显示英文枚举。  
10.4 禁止开发者自行定义中文名称并绕过术语表。  
10.5 禁止绕过 `i18n_zh.js` 直接输出用户可见文案。

## 11. 检查与门禁
11.1 提交前必须执行 `python3 scripts/check_ui_language.py`。  
11.2 标准执行入口为仓库根目录 `make v1-check-ui-language`。  
11.3 检查脚本命中违规项时，必须修复后再提交。  
11.4 若脚本误报，需在评审记录中说明具体原因，不得直接忽略。
