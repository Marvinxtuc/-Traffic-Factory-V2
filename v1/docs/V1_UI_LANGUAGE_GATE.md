# V1 中文门禁接入说明

## 1. 门禁目标
- 将中文 UI 规范从“文档约束”升级为“执行约束”。
- 防止英文回流、术语漂移、绕过 i18n。

## 2. 门禁执行入口
- 统一命令入口：仓库根目录 `Makefile`
- 命令：
  - `make v1-check-ui-language`：执行英文 UI 残留检查。
  - `make v1-runtime-smoke`：执行运行态最小回归（服务需先启动）。
  - `make v1-preflight`：串行执行上述两项检查。

## 3. 前端文案开发流程（强制）
1. 先在 `v1/web/assets/i18n_zh.js` 新增或更新术语。
2. 页面与脚本仅通过 `data-i18n` / `TFUI.t()` 引用术语 key。
3. 执行 `make v1-check-ui-language`。
4. 启动服务后执行 `make v1-runtime-smoke`。
5. 两项均通过后才允许提交。

## 4. 禁止流程
- 禁止在 `html/js` 直接新增硬编码文案（中文或英文）。
- 禁止不补术语表直接开发页面文案。
- 禁止跳过检测脚本直接提交。
- 禁止绕过 `i18n_zh.js` 输出用户可见文案。

## 5. 术语入口固化
- `v1/web/assets/i18n_zh.js` 是 V1 前端文案唯一入口。
- `discovery/topics/content` 三页面已按该机制落地。
- 后续新增页面必须先接入该机制，再开发可见文案。
- 若后续扩展多语言，必须以当前集中配置结构为基线扩展。
